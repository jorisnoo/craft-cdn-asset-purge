# Craft CDN Asset Purge

A [Craft CMS](https://craftcms.com) module that purges CDN URLs when assets are replaced, renamed, moved, or deleted. Works with [Bunny CDN](https://bunny.net) or any other CDN that has a purge API.

## Requirements

- Craft CMS 5.0+
- PHP 8.2+

## Installation

Install via Composer:

```bash
composer require jorisnoo/craft-cdn-asset-purge
```

Register the module in `config/app.php`:

```php
return [
    'modules' => [
        'cdn-asset-purge' => \Noo\CraftCdnAssetPurge\CdnAssetPurge::class,
    ],
    'bootstrap' => ['cdn-asset-purge'],
];
```

## Configuration

Create `config/cdn-asset-purge.php`:

```php
<?php

use craft\helpers\App;

return [
    'apiKey' => App::env('CDN_API_KEY'),
    'filesystems' => ['images'],
];
```

| Setting | Description | Default |
|---------|-------------|---------|
| `apiUrl` | The CDN purge API endpoint | `https://api.bunny.net/purge` |
| `apiKey` | Your CDN API key | — |
| `authType` | Auth header style: `access_key` or `bearer` | `access_key` |
| `filesystems` | Filesystem handles to monitor (asset and transform filesystems) | `[]` |

### Using a custom CDN

Override the API URL and auth type to point at any purge endpoint:

```php
return [
    'apiUrl' => 'https://cdn.example.com/api/cache/purge',
    'apiKey' => App::env('CDN_API_KEY'),
    'authType' => 'bearer',
    'filesystems' => ['images'],
];
```

## How it works

When an asset in a monitored filesystem is replaced, renamed, moved, or deleted, the module collects its old URL. Image transforms that Craft generated for the asset are purged too: whenever Craft deletes an asset's generated transform files (on replace, move, rename, delete or focal point change), their URLs are collected as long as the volume's transform filesystem is listed in `filesystems`.

At the end of the request (or after each queue job, for long-running queue workers), all collected URLs are pushed as a single queue job, which sends them to the configured API endpoint in batches of 100 URLs. The purge happens asynchronously so it doesn't block the control panel. Bulk operations such as moving a folder therefore create one job instead of one per asset.

Purge requests use a 10-second connect timeout and a 30-second request timeout. A failed request fails the queue job, which is retried up to 3 times.

Only transforms generated by Craft's built-in image transformer are tracked. Transforms served by third-party transformers (e.g. imgix) use their own URLs and are not purged.
